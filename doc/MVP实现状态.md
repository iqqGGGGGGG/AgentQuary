# AI 泛知识问答闯关 MVP 实现状态

更新时间：2026-08-04

## 当前结论

当前版本已经形成可完整演示的 MVP 闭环：输入主题或公开网页链接 → AI 生成题目 → 逐题作答与即时反馈 → 生成成绩报告 → 保存历史 → 查看错题或再次挑战。

后端已接入 MySQL 数据库，用户系统和学习记录云端持久化已完成。账号体系（微信登录）、云端同步、复杂文档解析、生产部署和系统级安全审计仍未完成。

## 已实现

- 支持主题文本、公开网页链接以及 `.txt` / `.md` 文件输入。
- 输入长度、空内容、文件大小与文件类型校验。
- 服务端抓取公开文本网页，并阻止 localhost、内网 IP 和非文本内容，降低 SSRF 风险。
- 题目结构校验：单选题固定 4 个选项，判断题固定 2 个选项，答案索引必须有效。
- 闯关过程支持即时正误反馈、解析、连续答对计数和中途退出后续玩。
- 报告支持得分、掌握点、薄弱点、AI 总结与错题展开复盘。
- 历史记录保留完整题目和报告，支持查看、重试、单条删除和全部清除。
- 微信分享入口、返回首页和“再来一关”均已接通。
- API 地址可通过 `TARO_APP_API_BASE_URL` 配置，不再写死局域网地址。
- 微信小程序与 H5 构建产物分别输出到 `dist/weapp` 和 `dist/h5`，避免互相覆盖。
- 增加本地 mock API，可在没有真实模型服务时演示完整流程。

## 本地运行

### 1. 前端配置

复制 `.env.example` 为 `.env`，按环境修改：

```env
TARO_APP_API_BASE_URL=http://127.0.0.1:8000
```

### 2. 微信小程序

```powershell
npm install
npm run dev:weapp
```

然后用微信开发者工具打开项目根目录。小程序产物位于 `dist/weapp`。

### 3. H5 + 本地 mock 演示

分别打开三个终端：

```powershell
npm run dev:mock-api
```

```powershell
npm run build:h5
```

```powershell
npm run preview:h5
```

访问 `http://127.0.0.1:4175/`。

### 4. 真实后端

```powershell
cd server
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

真实生成能力还需要在 `server/.env` 中配置模型服务密钥与模型参数，具体字段以 `server/config.py` 为准。密钥不得提交到仓库。

## 已验证

- TypeScript：`tsc --noEmit` 通过。
- 微信小程序：`npm run build:weapp` 通过。
- H5：`npm run build:h5` 通过。
- Python：关键后端文件通过 `py_compile` 语法检查。
- 浏览器端完整走通 3 道题流程，包括正确反馈、错误反馈、67% 报告、历史报告和两列响应式布局。

## 尚未完成与风险

- **后端测试未完整执行**：当前机器缺少项目 Python 依赖和 `pytest`，只完成了语法检查；上线前必须安装依赖并执行 `pytest`。
- **真实模型链路未验收**：本轮完整交互使用本地 mock API；必须用目标模型验证结构化输出稳定性、超时、限流、费用和失败重试。
- **文件能力有限**：只支持纯文本 `.txt` / `.md`，PDF、Word、图片 OCR 不在当前 MVP 范围。
- **网页抽取是基础实现**：动态渲染、登录墙、反爬页面及复杂正文抽取可能失败。
- **微信登录需真机验证**：dev_mode 下使用模拟 openid，真实微信登录流程需配置 AppID/Secret 并在真机上验证。
- **分享能力需真机验证**：H5 无法等价验证微信小程序分享卡片和生命周期。
- **H5 体积警告**：当前入口约 303 KiB，高于 Webpack 建议值；不阻塞 MVP，但正式发布前应做分包和依赖瘦身。
- **安全仍需复核**：已有 URL 公网校验和响应大小限制，但生产环境仍需出站网络策略、域名白名单、速率限制、日志脱敏与安全审计。

## 下一阶段建议

优先级不应是继续堆 UI 页面，而是先证明核心价值和生成可靠性：

1. 用真实模型跑一组固定主题回归集，统计生成成功率、题目合法率、平均耗时和单局成本。
2. 为 URL 抓取、题目 schema、进度恢复和历史迁移补齐自动化测试。
3. 在真实用户测试中验证"用户是否愿意完成一局并主动再来一局"，再决定排行榜和社交玩法。
4. 完成微信登录真机验证（配置 AppID/Secret，关闭 dev_mode）。
5. 达到稳定性门槛后，再加入 PDF/Word、生产监控和正式部署。
