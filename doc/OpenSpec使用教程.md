# OpenSpec 使用教程 —— 傻瓜版

> 本教程基于你的 AgentQuary 项目，教你用 OpenSpec 管理新功能开发。
> 前提：已安装 Node.js 20+ 版本。

---

## 一、OpenSpec 是什么？

一句话：**让 AI 先写"计划书"，你确认没问题后，再写代码。**

没有 OpenSpec 时，你和 AI 对话 → AI 直接写代码 → 结果可能跑偏 → 返工。
有了 OpenSpec，你和 AI 对话 → AI 先输出"提案/需求/设计/任务清单" → 你确认 → AI 按计划写代码 → 完成后归档。

---

## 二、安装（终端操作，只需一次）

### 2.1 全局安装 OpenSpec CLI

```bash
npm install -g @fission-ai/openspec@latest
```

### 2.2 在项目中初始化

```bash
cd E:\1_Project\AgentQuary
openspec init
```

初始化时会让你选择 AI 工具（如 Claude Code、Cursor 等），选你正在用的即可。

初始化完成后，项目根目录会多一个 `openspec/` 文件夹：

```
openspec/
├── specs/           ← 项目当前的行为规范（系统当前是怎么工作的）
│   └── (你的领域文件夹)
├── changes/         ← 每个新功能/变更的计划文件夹
└── config.yaml      ← 可选配置
```

---

## 三、核心流程（只需记住 3 个命令）

整个流程只有 **三步**，全部在 AI 聊天窗口中输入：

```
第1步：告诉 AI 你要做什么    →  /opsx:propose 功能名
第2步：让 AI 按计划写代码    →  /opsx:apply
第3步：完成后归档            →  /opsx:archive
```

就这样。下面是详细说明。

---

## 四、实战演示：为 AgentQuary 添加"错题本导出PDF"功能

### 第 1 步：提出变更（AI 聊天窗口）

在你的 AI 编码助手（Kilo/Cursor/Claude Code 等）的聊天框中输入：

```
/opsx:propose export-wrong-book-pdf
```

> `export-wrong-book-pdf` 是你给这次变更起的名字，用英文短横线连接，自己起一个有意义的名字就行。

AI 会自动：

1. 创建文件夹 `openspec/changes/export-wrong-book-pdf/`
2. 生成 4 个文件：

| 文件 | 作用 | 通俗解释 |
|------|------|----------|
| `proposal.md` | 提案 | 为什么要做？做什么？范围多大？ |
| `specs/` | 需求规范 | 具体要满足哪些需求？每个需求有哪些场景？ |
| `design.md` | 技术设计 | 怎么实现？用什么技术方案？ |
| `tasks.md` | 任务清单 | 具体要写哪些代码？列出 TODO 清单 |

**你要做的：读一遍这 4 个文件，确认 AI 理解对了。**

如果觉得有问题，直接告诉 AI 修改，比如：

```
proposal.md 里说"所有用户可用"，改成"仅VIP用户可用"
```

或者：

```
tasks.md 里缺少"添加按钮到错题本页面"这个任务，加上
```

### 第 2 步：执行实现（AI 聊天窗口）

确认计划没问题后，输入：

```
/opsx:apply
```

AI 会按照 `tasks.md` 中的清单逐项写代码，完成一项就勾一项：

```
✓ 1.1 创建 PDF 生成工具函数
✓ 1.2 添加错题数据查询接口
✓ 2.1 在错题本页面添加"导出"按钮
✓ 2.2 实现导出逻辑
✓ 2.3 添加导出进度提示
所有任务完成！
```

**过程中你可以随时打断、修改方向。** 比如发现设计有问题，可以先更新 `design.md`，再继续。

### 第 3 步：归档（AI 聊天窗口）

所有代码写完后，输入：

```
/opsx:archive
```

AI 会：

1. 把这次变更的需求规范合并到主规范 `openspec/specs/` 中
2. 把整个变更文件夹移动到 `openspec/changes/archive/2026-09-08-export-wrong-book-pdf/`

归档后，你的项目规范就更新了——以后 AI 看到规范，就知道系统支持导出 PDF 了。

## 五、还没想好做什么？用 /opsx:explore

如果你只有一个模糊的想法，不确定怎么实现，先用 **探索模式**：

```
/opsx:explore
```

AI 会：
- 分析你的代码库
- 给你几个可行方案
- 帮你比较优劣
- 等你想清楚后，再转到 `/opsx:propose`

示例对话：

```
你：/opsx:explore
AI：你想探索什么？
你：我想给错题本加点新功能，但不确定加什么好
AI：让我看看你的错题本模块...
    我发现几个方向：
    1. 错题导出 PDF（方便打印复习）
    2. 错题分类标签（按知识点归类）
    3. 错题重做（答对后自动移除）
    你对哪个感兴趣？
你：第1个，导出PDF
AI：好，运行 /opsx:propose export-wrong-book-pdf 开始
```

## 六、生成的文件长什么样？

### proposal.md（提案）

```markdown
# Proposal: Export Wrong Book PDF

## Intent
用户需要将错题本内容导出为 PDF，方便打印复习。

## Scope
- 错题本页面添加"导出PDF"按钮
- 生成包含错题题目、答案、解析的 PDF 文件
- 支持选择导出全部或指定错题

## Approach
使用小程序端 canvas 绘制 + 后端生成 PDF 文件的方式。
```

### specs/（需求规范）

```markdown
## ADDED Requirements

### Requirement: PDF Export
系统应允许用户将错题导出为 PDF 文件。

#### Scenario: 导出全部错题
- WHEN 用户点击"导出全部"按钮
- THEN 系统生成包含所有错题的 PDF 文件
- AND 用户可以下载该文件

#### Scenario: 导出指定错题
- WHEN 用户选中若干错题后点击"导出选中"
- THEN 系统仅导出被选中的错题
```

### tasks.md（任务清单）

```markdown
# Tasks

## 1. 后端
- [ ] 1.1 创建 PDF 生成 API 接口
- [ ] 1.2 实现错题数据查询逻辑

## 2. 前端
- [ ] 2.1 错题本页面添加导出按钮
- [ ] 2.2 实现调用导出接口的逻辑
- [ ] 2.3 添加导出中/完成的提示
```

## 七、常用命令速查表

### 终端命令（在项目根目录运行）

| 命令 | 作用 |
|------|------|
| `openspec init` | 初始化 OpenSpec（只需一次） |
| `openspec list` | 查看当前有哪些活跃的变更 |
| `openspec show <名称>` | 查看某个变更的详情 |
| `openspec validate <名称>` | 检查变更文件格式是否正确 |
| `openspec view` | 打开可视化控制台 |
| `openspec update` | 更新 AI 工具的技能文件 |

### AI 聊天命令（在 AI 助手聊天框输入）

| 命令 | 作用 | 何时用 |
|------|------|--------|
| `/opsx:explore` | 探索想法 | 还没想好做什么 |
| `/opsx:propose <名称>` | 创建变更计划 | 已经知道要做什么 |
| `/opsx:apply` | 按计划写代码 | 确认计划没问题后 |
| `/opsx:update` | 修改已有的计划 | 计划需要调整时 |
| `/opsx:verify` | 检查实现是否符合计划 | 归档前想检查一下 |
| `/opsx:archive` | 归档完成的变更 | 所有代码完成后 |
| `/opsx:onboard` | 交互式新手教程 | 第一次使用时 |

## 八、不同 AI 工具的命令写法

OpenSpec 支持 20+ 种 AI 工具，命令写法略有不同：

| 你用的工具 | 命令写法 |
|-----------|----------|
| Claude Code / Kilo / Gemini CLI | `/opsx:propose` `/opsx:apply` |
| Cursor / GitHub Copilot | `/opsx-propose` `/opsx-apply` |
| Codex CLI | `$openspec-propose` `$openspec-apply` |
| Amazon Q | `@opsx-propose` `@opsx-apply` |

> 初始化时 `openspec init` 会自动告诉你该用哪种写法。

## 十、注意事项

1. **命令在哪输入？**
   - `openspec xxx` → 在终端（PowerShell/CMD）输入
   - `/opsx:xxx` → 在 AI 助手的聊天框输入

2. **变更命名规范**
   - 用英文短横线连接：`add-dark-mode`、`fix-login-bug`
   - 不要用：`update`、`changes`、`wip` 这种太泛的名字

3. **不用一次做完**
   - 提案写了一半有事？没关系，下次继续
   - 实现到一半想改设计？直接改 `design.md`，再继续 `/opsx:apply`

4. **存量项目完全支持**
   - OpenSpec 专门设计了对已有项目的支持
   - `openspec init` 不会改动你现有的任何代码

5. **看不懂 AI 生成的规范？**
   - 直接告诉 AI 用中文写：`请用中文重写 proposal.md`
   - 或者在 `openspec/config.yaml` 中设置语言偏好
